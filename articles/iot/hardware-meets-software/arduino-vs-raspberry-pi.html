Arduino vs. Raspberry Pi

These two get lumped together constantly, and they solve different problems. An Arduino is a microcontroller board: it runs one compiled program, has no operating system, and boots in milliseconds. A Raspberry Pi is a single-board computer: it boots a full Linux operating system — the same kind of system you met in the Operating Systems Basics module, complete with a scheduler juggling many processes — and your program runs as one of them.

What that actually buys you

Arduino's lack of an OS is a feature, not a limitation, for a certain kind of job: real-time control where you need a predictable, unwavering response time — reading a sensor and firing an actuator on a strict schedule, with nothing else ever allowed to interrupt that loop. There's no scheduler deciding to give some other process a turn at a bad moment.

Raspberry Pi's Linux gets you everything an OS gives you: a file system, real networking, the ability to run Python or Node, drive a display, and run several things "at once." That flexibility costs you the same context-switching overhead and non-determinism you learned about in Scheduling — fine for most jobs, but not for a control loop that needs to fire an actuator at an exact, guaranteed instant.

In practice, real projects often use both together: an Arduino (or similar microcontroller) handling the fast, deterministic hardware interaction, talking to a Raspberry Pi that handles logic, a user interface, networking, and data logging.

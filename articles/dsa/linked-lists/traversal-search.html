Traversal & Search

Searching a linked list means the same thing it means for an array: walk it, comparing each value to the target, until you find a match or run out of nodes. The difference is that a linked list gives you exactly one way to do that walk — there's no shortcut available.

def search(head, target):
    current = head
    while current:
        if current.value == target:
            return current
        current = current.next
    return None

This is O(n) in the worst case, same as linear search on an array. But unlike an array, a linked list has no faster option — even if every value in the list happens to be sorted.

Why binary search doesn't work here

Binary search's entire speedup comes from jumping straight to the middle element — arr[(low+high)//2] — which is only possible because array elements have addresses you can compute directly. A linked list node has no address formula; the only way to reach "the middle" is to walk there one next at a time from the head, which already costs O(n) before you've made a single useful comparison. Halving a search space you can't jump into buys you nothing.

This is exactly why the Arrays module's Binary Search only works on arrays (or anything else with O(1) random access, like a balanced binary search tree navigated top-down) — not on singly or doubly linked lists.

Insert & Delete Operations

Every insert or delete on a linked list has two parts: getting to the spot (which costs O(n), since you have to walk pointers from the head) and relinking a few pointers once you're there (which costs O(1)). The overall cost depends entirely on how much walking the first part needs.

Insert at head

No walking required — you already have head.

def insert_at_head(self, value):
    new_node = Node(value)
    new_node.next = self.head
    self.head = new_node

O(1), full stop.

Insert at tail

A singly linked list with no separate tail pointer has to walk the whole chain to find the last node first.

def insert_at_tail(self, value):
    new_node = Node(value)
    if not self.head:
        self.head = new_node
        return
    current = self.head
    while current.next:
        current = current.next
    current.next = new_node

O(n) — the walk dominates. (Some implementations keep an explicit tail pointer specifically to make this O(1); the tradeoff is keeping that pointer correct through every delete.)

Insert after a node / delete a node

If you already hold a reference to the node (e.g. you're mid-traversal), relinking is O(1): point the new node's next at what the previous node pointed to, then repoint the previous node at the new one. Deleting a node (other than the head) means the previous node needs to skip over it — which means you need a reference to the previous node, not just the one being removed.

This is the source of the common misconception that "linked lists are fast to insert into." They're only O(1) once you already have a pointer to the right spot. Finding that spot — by index, by value, by any means other than already holding it — costs O(n), same as everything else in an unindexed structure.

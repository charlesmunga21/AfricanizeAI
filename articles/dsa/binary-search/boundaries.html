Finding Boundaries

The standard algorithm assumes the target appears at most once. Real data often has duplicates — and then "found it" isn't a complete answer. If you're looking up the start of a date range, or counting how many times a value occurs, you need the first or last occurrence specifically, not just any match.

The trick: don't stop at the first match

When arr[mid] == target, the standard algorithm returns immediately. To find the first occurrence instead, record that index as a candidate, then keep searching the left half in case there's an earlier match — high = mid - 1, not a return. To find the last occurrence, keep searching the right half instead — low = mid + 1. Either way, the loop only ends when low > high, and the last recorded candidate is the answer.

def find_first(arr, target):
    low, high, result = 0, len(arr) - 1, -1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            result = mid
            high = mid - 1        # keep looking left for an earlier match
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return result
This same "record a candidate, keep narrowing" pattern is exactly how bisect_left/bisect_right (Python's bisect module) and lower_bound/upper_bound (C++'s <algorithm>) work — this isn't a one-off trick, it's the general shape of every binary-search variant.

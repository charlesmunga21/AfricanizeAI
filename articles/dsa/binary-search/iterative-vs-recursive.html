Iterative vs. Recursive

Binary search can be written two ways: a loop that mutates low and high in place, or a function that calls itself on a smaller range. Both do the same comparisons in the same order — the difference is entirely about what happens in memory while the search runs.

Iterative

def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

One set of variables, reused every iteration. Space complexity: O(1).

Recursive

def binary_search(arr, target, low=0, high=None):
    if high is None:
        high = len(arr) - 1
    if low > high:
        return -1
    mid = (low + high) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search(arr, target, mid + 1, high)
    else:
        return binary_search(arr, target, low, mid - 1)

Every call that hasn't returned yet stays on the call stack, waiting for the one below it to finish. Space complexity: O(log n) — proportional to how deep the recursion goes, which is exactly the number of times you can halve n.

This is a general pattern, not specific to binary search: any recursive algorithm's space cost includes its maximum call stack depth, on top of whatever it explicitly allocates. An iterative version with an explicit loop variable instead of recursive calls avoids that cost entirely.

Visual model: watch the call stack

Run the recursive version and step through it — a frame is pushed onto the stack for every call, and popped when that call returns. Then try the iterative version on the same target: notice it never uses more than one frame.

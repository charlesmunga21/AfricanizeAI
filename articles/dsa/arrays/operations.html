Array Operations

Arrays support a small set of core operations. Their costs aren't uniform — some are O(1), some are O(n) — and the difference comes entirely from whether the operation has to preserve contiguity.

Access

Reading or writing arr[i] is O(1): direct address arithmetic, covered in the previous submodule.

Traversal

Visiting every element once — printing them, summing them, mapping a function over them — is O(n), since there are n elements and each is visited exactly once.

Insertion

Inserting at the end is O(1) if there's spare capacity: drop the value in, no other element moves. Inserting at the start or middle is O(n): every element from that index onward has to shift right one slot first, to make room while staying contiguous.

Deletion

Symmetric to insertion. Deleting from the end is O(1). Deleting from the start or middle is O(n), because everything after the removed slot has to shift left to close the gap.

Insertion and deletion in the middle are expensive precisely because of the property that makes access fast: contiguity. Move one element out of place, and everything after it has to move too. If your workload is insert/delete-heavy away from the end, a linked list is often the better fit — see linked lists.

Visual model: try each operation

Pick an index and value, then run an operation. Watch which boxes move, and how the reported complexity changes based on where the operation happens.

Code

arr = [10, 20, 30, 40, 50]

arr[1]              # access — O(1) -> 20
arr.append(60)       # insert at end — O(1)
arr.insert(0, 5)      # insert at start — O(n), shifts everything right
arr.pop()             # delete at end — O(1)
del arr[0]            # delete at start — O(n), shifts everything left

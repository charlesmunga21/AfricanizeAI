Introduction & Memory Layout

An array is a collection of elements stored in contiguous memory locations, all of the same type, and accessed using an index. It's the simplest possible way to group a fixed number of values together, and almost every other data structure — lists, stacks, queues, hash tables — is built on top of one.

Why contiguous memory matters

Because array elements sit next to each other in memory, the location of any element can be calculated directly from its index, instead of being searched for. If an array starts at memory address base and each element takes up size bytes, the address of element i is:

address(i) = base + (i * size)

This is why reading or writing arr[i] takes constant time, O(1), regardless of how large the array is — there's no traversal, just arithmetic.

Contrast this with a linked list, where elements can live anywhere in memory and are connected by pointers. That flexibility is what makes insertion cheap in a linked list and expensive in an array — see linked lists for the full tradeoff.

Static vs. dynamic arrays

A static array has a fixed size decided at creation — the memory block is allocated once. A dynamic array (Python's list, JavaScript's Array, C++'s std::vector) looks like it can grow freely, but under the hood it's still a contiguous block: when it runs out of room, the runtime allocates a new, larger block (usually double the size) and copies everything over. That occasional copy is why dynamic array growth is amortized O(1) per append, even though any single append can occasionally cost O(n).

Example

scores = [72, 88, 95, 61, 79]
print(scores[2])   # O(1) — direct address calculation -> 95

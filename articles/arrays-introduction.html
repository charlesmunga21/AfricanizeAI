Arrays

An array is a collection of elements stored in contiguous memory locations, all of the same type, and accessed using an index. It's the simplest possible way to group a fixed number of values together, and almost every other data structure — lists, stacks, queues, hash tables — is built on top of one.

Why contiguous memory matters

Because array elements sit next to each other in memory, the location of any element can be calculated directly from its index, instead of being searched for. If an array starts at memory address base and each element takes up size bytes, the address of element i is:

address(i) = base + (i * size)

This is why reading or writing arr[i] takes constant time, O(1), regardless of how large the array is.

Core operations and their cost

  • Access by index — O(1). Direct address calculation, no traversal needed.
  • Search (unsorted) — O(n). You may have to check every element.
  • Search (sorted) — O(log n) using binary search.
  • Insert/delete at the end — O(1) if there's spare capacity.
  • Insert/delete at the start or middle — O(n), since every following element has to shift to keep the array contiguous.
Insertion and deletion are expensive precisely because of the property that makes access fast: contiguity. Shift one element out of place, and everything after it has to move.

Example: linear search vs. direct access

def find_index(arr, target):
    for i, value in enumerate(arr):
        if value == target:
            return i
    return -1

scores = [72, 88, 95, 61, 79]
print(scores[2])          # O(1) -> 95
print(find_index(scores, 61))  # O(n) -> 3

When to reach for an array

Use an array when the number of elements is known or bounded, when you need fast random access by index, and when insertions/deletions mostly happen at the end. If you need frequent insertions in the middle of the collection, a linked list or a different structure is usually a better fit — see the linked lists tutorial for the tradeoff.

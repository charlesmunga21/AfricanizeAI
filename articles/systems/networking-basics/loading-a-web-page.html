Loading a Web Page, Start to Finish

You type a web address and hit enter. Less than a second later, a page appears. Here's everything from this module, happening in order, in that one short moment.

The five steps

  1. DNS lookup — your browser asks "what's the address for this name?" and gets an IP address back, either freshly or from its cache.
  2. Routing — your request is split into packets and hops across a chain of routers toward that address.
  3. The server — a computer on the other end receives the request. To build the actual page, it might even need to ask its own database — like the Postgres server from the Databases submodule — for the content.
  4. The response — the answer travels back the same way, split into packets again.
  5. Rendering — your browser reassembles the packets in order and draws the finished page on your screen.

Every one of those five steps costs a little time — a DNS lookup, several router hops there, server processing, several router hops back. That's the latency you learned about in the last submodule, stacked up step after step. And yet, on a decent connection, this whole chain usually finishes in well under a second.

This is the payoff of the whole Computer Functions section so far: a web request touches nearly everything you've learned — a CPU running instructions, RAM and cache holding data close by, disk storing it permanently, and now a network carrying it between machines entirely. None of these ideas exist in isolation; every real system leans on all of them at once.

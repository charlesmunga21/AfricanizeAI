Packets & IP Addresses

When you send something over a network — a message, a photo, a request for a web page — it doesn't travel as one single blob. It gets sliced into small pieces called packets, each one sent off on its own, and put back together in the right order once every piece has arrived.

Why not just send it as one piece?

Picture mailing a long letter by tearing it into a stack of numbered postcards and dropping them in the mail separately, instead of one big envelope. That sounds strange for a letter — but for data, it's genuinely useful:

  • If one small packet gets lost or damaged along the way, only that piece needs to be resent — not the entire file.
  • Many different conversations can share the same wires fairly, packet by packet, instead of one huge transfer hogging the connection the whole time.
  • Different packets from the same message can even take slightly different paths and still all arrive — they just get sorted back into order using their sequence number once they land.

Every packet needs an address: the IP address

For a packet to find its way, every device on a network needs a unique address — an IP address (like 192.168.1.5 on a home network, or a public one for a server out on the internet). It works exactly like a street address: it's how a packet knows where it's headed, and it's how the reply knows where to come back to.

Visual model: split a message, then reassemble it

Type a short message, send it, and watch it split into packets that arrive out of order — then reassemble them using their sequence numbers.

This is exactly the same principle you saw with SQLite and Postgres reading fixed-size pages from disk instead of the whole file at once — breaking big things into small, individually-addressable pieces shows up everywhere in computing, not just networks.

CPU Cache

The CPU is astonishingly fast. Plain RAM, by comparison, is slow — not slow in human terms, but slow compared to the CPU. If the CPU had to reach all the way out to RAM for every single piece of data it needed, it would spend most of its time just waiting. The fix is the cache: a small pocket of extremely fast memory built directly onto the CPU chip itself, so close it barely takes any time to reach.

A notepad, not a filing cabinet

Think of the CPU cache as a notepad sitting right at your elbow, versus RAM as a filing cabinet across the room. You don't put a copy of every document on your notepad — just the handful you're actively using right now. Whenever the CPU needs a piece of data, it checks the notepad first. If it's there, that's called a cache hit — almost instant. If it's not, that's a cache miss, and the CPU has to make the slower trip out to RAM — and while it's there, it copies that data onto the notepad too, in case it's needed again soon.

Real CPUs actually have a few of these notepads stacked in size — a tiny, blazing-fast one (called L1) right on the core, a slightly bigger and slightly slower backup (L2), and often a larger shared one (L3) for the whole chip. You don't need to memorize the levels; the idea is the same at every level — smaller and closer trades capacity for speed.

Why this one idea explains so much about computer speed

The gap between "on the notepad" and "in the filing cabinet" is enormous — and it only gets bigger once you add disk into the picture. Brendan Gregg's book Systems Performance makes this vivid with a simple trick: scale every latency up so that a CPU cache reference takes 1 second, and see what the others become.

That's not a rounding error — reaching RAM instead of cache is the difference between "instant" and "put the kettle on," and reaching disk is the difference between "instant" and "wait for a package to ship." This single fact — cache is dramatically faster than RAM, and RAM is dramatically faster than disk — is the reason almost every fast piece of software, databases very much included, is obsessively designed around keeping frequently-used data as close to the CPU as possible.

Source: latency figures adapted from Brendan Gregg, Systems Performance (O'Reilly) — exact numbers vary a little by hardware generation, but the relative gaps between cache, RAM, and disk have stayed roughly this dramatic for years.

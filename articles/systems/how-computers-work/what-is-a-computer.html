What Is a Computer?

Strip away the screen, the apps, and the icons, and a computer is doing one very simple thing over and over: it takes some input, follows a list of instructions (a program) to process that input, and produces some output. Along the way, it needs somewhere to hold things it's currently working on, and somewhere to keep things permanently. That's really the whole story — everything else is detail.

The five jobs, and the four parts that do them

Every computer, from a phone to a server rack in a data centre, needs to do the same five things:

  • Take input — a keyboard press, a tap, a camera frame, a request arriving over the internet.
  • Compute — actually do something with that input. This is the CPU's job.
  • Remember things it's using right now — the program's current state, the data it's working on. This is RAM's job (with a tiny, even faster helper called cache sitting right on the CPU itself).
  • Keep things permanently — files, installed apps, database records — so they're still there after a restart. This is the disk's job.
  • Produce output — a picture on a screen, a sound, a saved file, a reply sent back over the network.

The next four submodules each take one of these physical parts — CPU, cache, RAM, disk — and explain it on its own. This page is just the map.

A concrete example

Say you tap "open" on a photo. Input (your tap) tells the CPU to run the photo app's instructions. The CPU asks the operating system to load the app and the image file from disk into RAM, because RAM is far faster to work from than disk. As the CPU decodes and draws the image pixel by pixel, it leans on its own tiny cache to avoid constantly reaching all the way out to RAM. Finally, the finished picture is sent to the screen — the output.

Keep that example in your head. Every one of the next four submodules is really just zooming into one step of it — and the final submodule does the exact same walk-through, except the "app" is a database like SQLite or Postgres, and the "photo" is a row of data.

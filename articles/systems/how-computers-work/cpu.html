The CPU

The CPU (Central Processing Unit) is the part of the computer that actually does things — often called "the brain." Physically, it's a chip covered in billions of microscopic switches. But you don't need to think about the switches. What matters is what the CPU does with them: it runs one simple, tireless loop, over and over, billions of times a second.

The loop: fetch, decode, execute, store

A program is really just a long list of tiny instructions — "add these two numbers," "compare this to that," "move this piece of data over there." The CPU works through that list one instruction at a time, and each instruction goes through the same four steps:

  • Fetch — grab the next instruction from memory.
  • Decode — figure out what it's asking for.
  • Execute — actually do it.
  • Store — write the result somewhere it can be used next.

Then it fetches the next instruction, and does it all again. That's it — that's the whole trick. A CPU doesn't "understand" a program the way you understand a recipe; it just tirelessly marches through millions of these tiny, dumb steps, and the illusion of intelligence emerges from doing that unbelievably fast.

What "GHz" and "cores" actually mean

A CPU's clock speed (say, 3.5 GHz) is just how many times per second it can run through that fetch-decode-execute-store loop — 3.5 billion times a second, in that example. A "core" is a full, independent copy of this whole machinery. A CPU with 8 cores is really 8 small brains that can each run their own loop at the same time, which is why modern computers can genuinely do several things in parallel rather than just switching between them very quickly.

Here's the catch: every single one of those fetch and store steps normally means reaching out to memory to get or put data — and memory is much slower than the CPU itself. If the CPU had to wait for plain RAM on every single step, it would sit idle most of the time. That problem, and its fix, is exactly what the next submodule — CPU Cache — is about.

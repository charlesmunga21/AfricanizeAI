Operating Systems Basics

Your computer is running dozens of programs "at once" — a browser, a chat app, a music player, maybe a database server — on a machine with far fewer CPU cores than that. Something has to decide who gets the CPU, give each program its own private slice of memory, and organize the disk so files don't collide. That referee is the operating system, and this module explains how it does its job, in plain language.

This module closes the loop on the whole Computer Functions section: it's the OS that actually hands out the CPU, cache, RAM, disk, and network from the earlier two modules to every program that asks. Grounded, like the rest of this section, in Brendan Gregg's Systems Performance and PlanetScale's engineering blog by Ben Dicken — this time his post on how Postgres and MySQL each handle connections.

Quick reference

TermPlain-English meaning
ProcessOne running instance of a program, with its own private memory
ThreadA lighter-weight worker inside a process, sharing that process's memory
SchedulerThe part of the OS that decides which process gets the CPU next
Virtual memoryThe illusion that lets every process believe it has the whole memory to itself
File systemThe OS's way of organizing raw disk space into named, findable files

What Is an Operating System?

Right now, your computer is probably running a browser, a chat app, some background updater, maybe music — all "at once," on a chip with maybe 8 CPU cores. None of those programs know about each other. None of them wrote code to politely take turns or divide up memory fairly. Something else is doing that job for them: the operating system (Windows, macOS, Linux, Android, iOS).

A referee with special privileges

The operating system is itself a program — but a special one, with privileges no ordinary app gets. It's the only thing allowed to talk to the hardware directly. Every other program has to ask it for what it needs: "give me some memory," "let me read this file," "send this over the network." The OS decides who gets what, and when — which is exactly what keeps a browser tab from accidentally overwriting your music player's memory, or hogging every last bit of the CPU.

What it's actually managing

Everything in this module is really the OS managing the same four things from the earlier modules, just now shared across many programs instead of one:

  • The CPU — who gets to run right now, and for how long (this module's Scheduling submodule).
  • RAM — how it's divided up, and how each program is kept from seeing another's data (Virtual Memory).
  • Disk — how raw storage becomes organized, named files (Files & the File System).
  • The network — which program's request a reply belongs to, and where it should be delivered.

Opening an App, Start to Finish

You double-click an icon. A moment later, a window appears, ready to use. Here's everything from this module — and quietly, from the whole Computer Functions section — happening in that short moment.

The six steps

  1. Find it — the OS looks up the app's files on disk, using the file system's index.
  2. New process — the OS creates a new process for it, with its own private, virtual slice of memory.
  3. Load in — the app's actual code is read from disk into that process's memory.
  4. Get a turn — the scheduler adds the new process to the rotation and eventually gives it a turn on the CPU.
  5. Run — the CPU executes its instructions, leaning on cache and RAM exactly as you saw in the first module.
  6. On screen — output reaches the display, and the app is open and responsive.

This is the payoff of the entire Computer Functions section. Opening an app touches nearly everything you've learned across all three modules: a CPU running instructions with cache and RAM close by, disk storing everything permanently through a file system, a network carrying data between machines when needed, and now an operating system tying all of it together — deciding who gets the CPU, handing out private memory, and organizing the disk. None of these ideas work in isolation; every real program you use leans on all of them, every time.

Virtual Memory

Open your task manager and you might see ten programs, each seemingly convinced it can use huge amounts of memory, starting from address zero, as if it were the only thing running. That's not a coincidence — it's a deliberate illusion the operating system maintains, called virtual memory.

Everyone gets their own private illusion

Every process is handed its own private range of memory addresses to use, called its virtual address space. When that process asks for "address 0x40," the OS (with help from the CPU) quietly translates that into wherever the data actually lives in the computer's real, physical RAM — a location the process never sees or needs to know about. Two completely different programs can both use "address 0x40" and never collide, because underneath, they're mapped to two totally different real locations.

Why bother with the illusion?

  • Safety — one program can't accidentally (or maliciously) read or overwrite another's memory, because it can't even address it.
  • Simplicity — every program gets to assume it has a clean, private, generously-sized memory space, without needing to coordinate with every other running program about who owns what.
  • Flexibility — the OS is free to physically move a process's data around in real RAM, or even temporarily shuffle rarely-used parts out to disk, without the program ever noticing — the mapping is simply updated underneath it.

Visual model: same address, different reality

Click each program to see what address it believes it's using — and where that's really mapped in physical RAM.

This is the same "keep it small and give out only what's currently needed" spirit you saw with RAM's limited capacity in the RAM submodule — virtual memory is the mechanism that lets the OS enforce that fairly and safely across many programs at once.
